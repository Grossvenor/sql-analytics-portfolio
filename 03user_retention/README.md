Retention и повторные заказы пользователей
 Цель кейса
Проанализировать поведение пользователей:
- возвращаются ли они за повторными заказами
- через какое время происходит повторный заказ

Кейс демонстрирует работу с:
- оконными функциями (LAG)
- датами и временем
- анализом пользовательской активности

---
 Используемые данные

Таблица: `user_actions`

Основные поля:
- `user_id` — идентификатор пользователя
- `order_id` — идентификатор заказа
- `time` — время действия
- `action` — тип действия пользователя

В анализе используются **только события `create_order`**.

---

 Логика решения
 Отбор заказов
Из таблицы `user_actions` отбираются только события создания заказов.
Время заказа приводится к типу `date`.

**Уровень агрегации:**  
1 строка = 1 заказ пользователя

### Шаг 2. Предыдущий заказ пользователя
С помощью оконной функции `LAG()` определяется дата предыдущего заказа пользователя.

```sql
LAG(order_date) OVER (
    PARTITION BY user_id
    ORDER BY order_date
)
