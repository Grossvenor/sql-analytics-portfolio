 Кейс 4 — Воронка пользователей (Funnel / Conversion)

  Цель кейса
Построить воронку пользовательских действий и рассчитать конверсию между этапами.

Кейс демонстрирует:
- построение funnel-аналитики
- работу с CASE WHEN и FILTER
- правильный уровень агрегации (пользователь)

---

🗂 Используемые данные

Таблица: `user_actions`

Основные поля:
- `user_id` — идентификатор пользователя
- `action` — действие пользователя

---

 Этапы воронки

1. **Visit** — пользователь совершил любое действие
2. **Create order** — пользователь создал заказ
3. **Cancel order** — пользователь отменил заказ

Каждый пользователь может пройти или не пройти любой из этапов.

---

 Логика решения

. Подготовка событий
Используются все действия пользователей без фильтрации по времени.

**Уровень агрегации:**  
1 строка = 1 пользователь

---

 Формирование флагов этапов
Для каждого пользователя создаются бинарные флаги:

- `step_visit` — был ли пользователь в сервисе
- `step_create_order` — создавал ли заказ
- `step_cancel_order` — отменял ли заказ

Флаги формируются с помощью `CASE WHEN` и агрегируются через `MAX()`.

---

 Расчёт метрик
Считается:
- количество пользователей на каждом этапе
- конверсия между этапами
