
 Описание кейса

Кейс посвящён анализу поведения пользователей в системе заказов.
Цель — понять, как со временем меняется количество созданных и отменённых заказов у каждого пользователя.

Кейс демонстрирует:
- работу с оконными функциями
- понимание уровня агрегации
- построение накопительных метрик
- корректную работу с временными данными

---

 Используемые данные

Таблица: `user_actions`

Колонки:
- `user_id` — идентификатор пользователя
- `order_id` — идентификатор заказа
- `action` — действие пользователя (`create_order`, `cancel_order`)
- `time` — время действия

---

 Постановка задачи

Для каждого действия пользователя необходимо:
1. Посчитать накопительное количество созданных заказов
2. Посчитать накопительное количество отменённых заказов
3. Сохранить уровень агрегации: **1 строка = 1 действие пользователя**
4. Упорядочить данные по пользователю и времени

---



 Уровень агрегации
Агрегация не используется (`GROUP BY` отсутствует), так как анализ ведётся на уровне отдельных действий пользователей.

оконные функции
Для расчёта накопительных метрик применяются оконные функции `COUNT() OVER()` с:
- `PARTITION BY user_id`
- `ORDER BY time`
- явным указанием оконного фрейма


FILTER
Используется `FILTER (WHERE ...)` для разделения логики подсчёта созданных и отменённых заказов без усложнения запроса.

---


Используемые SQL-инструменты

- `COUNT(*) FILTER (WHERE ...) OVER`
- `PARTITION BY`
- `ORDER BY`
- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`
- оконные функции
